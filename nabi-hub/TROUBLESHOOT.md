# 🔧 عیب‌یابی «ربات استارت می‌زنم ولی هیچی نمی‌شود»

این راهنما دقیقاً برای علامتی است که گزارش کردید. مراحل را به ترتیب اجرا کنید.

## قدم ۰ — عیب‌یاب خودکار (مهم‌ترین قدم)

در پوشهٔ پروژه (کنار فایل `.env`):

```bash
pip install -r requirements.txt
python check_bot.py
```

این اسکریپت ۵ چیز را واقعاً چک می‌کند و نتیجه را فارسی چاپ می‌کند:

1. **اعتبار توکن** — مستقیماً از تلگرام `getMe` می‌گیرد
2. **وضعیت Webhook روی توکن** — اگر جایی وب‌هوک ست شده باشد، تلگرام آپدیت‌ها را به آن URL می‌فرستد و ربات Polling شما هرگز چیزی نمی‌گیرد (شایع‌ترین علت «هیچی نشدن»)
3. **MAIN_ADMIN_ID** — واقعی است یا نمونه
4. **اتصال دیتابیس** + شمارش کاربران/فایل‌ها
5. **اتصال Redis** (اختیاری)

خروجی را بفرستید تا دقیق بگویم مشکل کجاست.

## قدم ۱ — شایع‌ترین علت‌ها (به ترتیب احتمال)

### ① روی توکن، وب‌هوک قدیمی فعال است (تداخل Polling/Webhook)
تلگرام برای هر توکن فقط یک مسیر تحویل دارد. اگر قبلاً نسخهٔ Webhook را ست کرده‌اید
(مثلاً `WEBHOOK_URL` روی Railway پر بود) و حالا Polling اجرا می‌کنید، آپدیت‌ها به URL قدیمی
می‌روند و ربات شما «هیچی» نمی‌بیند.

**نسخهٔ جدید این مشکل را خودکار حل می‌کند:** قبل از شروع Polling، `getWebhookInfo` لاگ می‌شود و `deleteWebhook` اجرا می‌شود. اگر در لاگ `⚠️ وب‌هوک تنظیم شده` دیدید، یعنی همین بود.

### ② `WEBHOOK_URL` بدون endpoint عمومی HTTPS
اگر `WEBHOOK_URL` ست است ولی سرویس شما آدرس عمومی HTTPS ندارد (مثلاً اجرای محلی)،
تلگرام آپدیت‌ها را به آن آدرس می‌فرستد و هیچ‌جا دریافت نمی‌شود.

**راه‌حل فوری:** `WEBHOOK_URL` را خالی کنید و `RUN_MODE=polling` بگذارید. نسخهٔ جدید پیش‌فرض را روی Polling گذاشته است.

### ③ توکن یا MAIN_ADMIN_ID اشتباه/نمونه
- توکن باید کامل و بدون فاصله/گیومه باشد: `123456789:AA...`
- `MAIN_ADMIN_ID` باید شناسهٔ عددی **خود شما** باشد (از [@userinfobot](https://t.me/userinfobot) بگیرید)، نه `111111111`
- نکتهٔ مهم: اگر `MAIN_ADMIN_ID` شما نباشد، دستور `/panel` پاس داده **نمی‌شود** (فیلتر ادمین) و همین «هیچی» به نظر می‌رسد.

### ④ توکن درست است ولی ربات اصلاً بالا نیامده
لاگ اجرا را ببینید. نسخهٔ جدید قبل از شروع، توکن را با `getMe` تست می‌کند:

```
🚀 در حال راه‌اندازی Nabi Hub | Uploader ...
🧭 حالت اجرا: POLLING
🗄 دیتابیس آماده است.
🤖 توکن معتبر است: @YourBot
▶ شروع Polling ...
```

اگر قبل از `▶ شروع Polling` خطا دیدید، همان را بفرستید.

### ⑤ DATABASE_URL خراب → کرش در لحظهٔ استارت
اگر Railway متغیر `DATABASE_URL` را به‌صورت `postgresql://...` بدهد، نسخه‌های قبلی
در لحظهٔ استارت کرش می‌کردند. **نسخهٔ جدید به‌طور خودکار آن را به
`postgresql+asyncpg://...` نرمال می‌کند** (این خرابی را در تست بازتولید و رفع کردم).

## قدم ۲ — تست سریع سیم‌کشی (بدون تلگرام)

اگر خواستید مطمئن شوید هندلرها وصل‌اند (شبیه‌سازی کامل آپدیت /start):

```bash
python tests/test_e2e.py
```

این تست `/start`، دیپ‌لینک ناشناس و دکمهٔ پنل ادمین را با Bot ساختی اجرا می‌کند و
API callهای خروجی را چاپ می‌کند.

## قدم ۳ — حالت DEBUG_ECHO

در `.env` بگذارید:

```
DEBUG_ECHO=1
```

حالا `/start` بزنید؛ اگر سیم‌کشی درست باشد فوراً این را می‌گیرید:

```
✅ اتصال برقرار است! آپدیت /start دریافت شد.
chat_id شما: 123456789
```

- **اگر این پیام آمد** → ربات سالم است؛ `DEBUG_ECHO=0` کنید و `MAIN_ADMIN_ID` را با همان chat_id ست کنید.
- **اگر نیامد** → آپدیت به ربات نمی‌رسد → مشکل ۱۰۰٪ حمل‌ونقل است (وب‌هوک/توکن/اجرا نبودن)، نه هندلرها.

## چک‌لیست Railway

- [ ] `BOT_TOKEN` و `MAIN_ADMIN_ID` در تب Variables ست شده‌اند
- [ ] `DATABASE_URL` = `${{Postgres.DATABASE_URL}}` (رفرنس سرویس)
- [ ] `RUN_MODE` = `polling` (پیش‌فرض) یا `webhook` + `WEBHOOK_URL` معتبر
- [ ] در Deployments → Logs پیام `▶ شروع Polling` را می‌بینید
- [ ] دو نسخهٔ همزمان از یک توکن روی دو سرویس اجرا نکرده‌اید (هر دو GetUpdates می‌گیرند و تداخل می‌سازند)
